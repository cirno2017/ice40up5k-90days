# commit-17：直接验证 debounce 消抖模块

## 计数规格

定义 **N = CNT_MAX + 1**。

- 消抖逻辑需**连续 N 个上升沿**采到与当前 `stable` 相反的同步输入，才更新 `stable`；
- 中途只要采到一次与 `stable` 相同的值，就**清零重新计数**；
- 默认 `CNT_MAX = 119999`，对应 12 MHz 下标称 **10 ms** 的消抖计数时间；
- 输入路径上还有 `sync_bit` 两级同步链，延迟 2 拍，**另外计算**（不计入 N）。

`fall_pulse`（按下事件）在 `stable` 由 1 更新为 0 的那一拍组合产生，宽度 1 拍。

### N=1 边界的位宽处理

`CNT_MAX=0` 时 `$clog2(CNT_MAX+1) = $clog2(1) = 0`，计数器位宽会为 0。
`rtl/debounce.v` 中已把位宽下限钳位为 1：

```systemverilog
localparam integer CNTWIDTH = (CNT_MAX > 0) ? $clog2(CNT_MAX + 1) : 1;
```

此时语义为：1 个不一致样本即采信新电平（`debounce_cnt == 0 == CNT_MAX` 恒成立）。

## 测试方法

- 入口：`make dsim`。构建两个独立 Verilator 模型，二进制名带 N，切换参数必重建：
  - `build/verilator_debounce_n4/Vdebounce_n4`（`CNT_MAX=3`，即 **N=4**，主测试）
  - `build/verilator_debounce_n1/Vdebounce_n1`（`CNT_MAX=0`，即 **N=1**，边界）
- 测试程序 `sim/debounce_main.cpp`：C++ 驱动 `btn`（只在非时钟边沿改变）。
- **参考模型用"连续不一致样本数"描述规格，不读取 DUT 内部计数器**：
  - 输入路径：第 k 拍的样本 = 第 k-2 拍采到的 `btn`（两级同步链延迟）；
  - `run` = 连续与 `stable` 不一致的样本数；不一致则 `run+1`，达到 N 即采信并清零；一致则清零；
  - 逐拍比对 DUT 的 `stable`、`fall_pulse`（仅失配时打印），并统计实际按下事件数。

## 定向场景与正常结果（N=4）

"样本"指消抖逻辑在上升沿实际采到的同步输入（经 2 拍同步链延迟）。

| 场景 | 预期 | 结果 |
|---|---|---|
| 初始未按下，持续为高 | `stable=1`，无事件 | PASS |
| 低电平仅持续 3 个样本后恢复高 | 不接受按下 | PASS（无事件） |
| 低电平连续达到 4 个样本 | 第 4 个样本处更新，1 次按下事件 | PASS（事件 t=205，逐拍比对保证恰好落在第 4 个样本） |
| 低 3 拍、高 1 拍、再低 4 拍 | 前一段计数取消，后一段重新计数 | PASS（高样本处无事件；事件 t=491 出现在重新计满后） |
| 持续按下很多拍 | 不重复产生事件 | PASS |
| 释放时反复抖动（高段最长 2 个样本），最终持续高 | 抖动期间不提前释放；达到门限后释放；不产生按下事件 | PASS |
| 完整释放后再次按下 | 再产生 1 次按下事件 | PASS（事件 t=755） |

汇总：全程共 **3 次按下事件**（场景 3/4/7 各 1 次），与规格一致。

## 变异测试：验证测试能发现连续性错误

**变异**：把"输入回到当前稳定值时清零计数"改为"保持计数"——

```systemverilog
end else begin
  debounce_cnt <= debounce_cnt;  // 变异: 一致时保持计数(规格应为清零)
end
```

**结果**：测试如预期失败（15 项 FAIL），`make dsim` 返回非 0。关键证据：

```
FAIL: t=458  场景4: 再低第3拍：stable=0 fall=1, 期望 stable=1 fall=0
FAIL: t=469  场景4: 再低第4拍：stable=0 fall=0, 期望 stable=1 fall=0
FAIL: t=480  场景4: 保持按住：stable=0 fall=0, 期望 stable=1 fall=0
FAIL: t=491  场景4: 保持按住：stable=0 fall=0, 期望 stable=0 fall=1
```

"低 3、高 1、低 4"用例失败：前一段 3 个低样本的计数未被高样本清零（保持为 3），
后一段第 1 个低样本（t=458）就错误越限，而不是重新计满 4 个样本（t=491）。
场景 2 残留的计数同样使场景 3 在第 1 个低样本处（t=172）提前采信，早于规格的第 4 个样本（t=205）。

**恢复**：把变异改回 `debounce_cnt <= '0;` 后重新运行，N=4 与 N=1 均全部通过；
系统级回归 `make vsim DIV=4` / `DIV=7` 与 `make vlint` 也全部通过。
